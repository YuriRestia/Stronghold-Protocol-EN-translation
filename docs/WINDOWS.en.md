# Windows portable bundle (zero-install)

> English translation of [WINDOWS.md](WINDOWS.md). The Chinese original is the authoritative version.

This document explains how to build a Windows portable bundle that needs "nothing installed on the target machine", what goes in it and what doesn't, and the licensing you need to confirm before sending it out.
Related code: `scripts/make-windows-bundle.mjs` (packaging) and `scripts/launch.mjs` (prepare + start the server + open the browser).

## 1. What this bundle is for

The portable bundle does exactly one thing: **make this Windows PC the server**. The bundle ships its own Node, assets and production dependencies, so nothing needs to be installed on the target machine.
Double-click `启动游戏.bat` ("Start Game.bat") to host on this machine and open the browser automatically; the console prints LAN addresses you can send to friends
(for playing alone, or with friends in the same dorm / office).

**You don't need this bundle to join someone else's server**: just open their URL in a browser — the same as typing any URL into your browser.
Nothing needs to run locally and no assets need downloading. That is why the bundle has no "connect to server" entry.

## 2. Building a portable bundle

First prepare the assets (`public/assets`, `public/fonts` and `public/vendor` are not in version control):

```bash
node tools/setup.mjs
```

Then, inside the repository (**on any platform**, as long as it has Node 22+ and internet access to download the official Node archive), run:

```bash
node scripts/make-windows-bundle.mjs                    # output defaults to <repo's parent>/Stronghold-Protocol-Windows
node scripts/make-windows-bundle.mjs --out D:\Game\Stronghold-Protocol-Windows --force
node scripts/make-windows-bundle.mjs --no-node          # skip the portable Node when the target machine already has Node 22+
node scripts/make-windows-bundle.mjs --node-version v22.23.3 --sha256 <64 hex digits>   # use another Node version
```

Give `--out` a **dedicated directory** (like above: a subdirectory under some parent directory). With `--force` it deletes the directory in only two cases:
the directory is empty, or it contains exactly the previous portable bundle (the bundle root has `README-开箱即用.md` and `app\`).
In every other case it refuses and tells you why — so a slip that points `--out` at the repository, the desktop or any other directory with content can't get them deleted by `--force`.
Pointing it at the repository itself or a parent of the repository is blocked at the very first step.

The output is always a **Windows** bundle (containing a win-x64 `node.exe`), but it **can be built on macOS / Linux**:
the layout of the extracted official archive is always `<zip name>/node.exe`, regardless of the packaging machine's OS.

Output contents:

```
node\node.exe            Official Windows x64 portable Node (version and sha256 pinned in the repo; only node.exe is taken)
node\LICENSE-node.txt    Node's own license (MIT, from the same official archive as node.exe)
app\                     The game itself: code + production dependencies + public (all assets) + data, fully offline
启动游戏.bat             ("Start Game.bat") app\scripts\launch.mjs --no-setup
README-开箱即用.md       ("README - ready to use") instructions for players (incl. the unofficial / no-profit / asset copyright notice)
LICENSE / NOTICE.md / THIRD-PARTY-NOTICES.md
```

Copy the whole folder to the target computer — **nothing to install**; just double-click `启动游戏.bat` (equivalent to `app\scripts\launch.mjs --no-setup`:
the assets are already in the bundle, so the online preparation is skipped and it goes straight to starting the server and opening the browser).
Uninstall = delete the folder (nothing is written to the registry or system directories). The ~330 MB of assets is an unavoidable cost, so the bundle is fairly large.

## 3. What goes in the bundle and what doesn't

The file list for `app\` comes from **`git ls-files`**, not a hand-written skip list. So local files kept out of version control by `.gitignore`
(`.env`, `.venv*`, `.claude/`, `scripts/service.env.cmd` …) **naturally can't get into the bundle** —
they may contain secrets or local paths. The old implementation copied the whole tree with a narrow exclusion list, and missing one entry meant packing it into the archive other people download.

On top of that, three resources that are not in version control but are required by the game are added, plus **freshly installed production dependencies** from `npm ci --omit=dev`:

* `public/assets`, `public/fonts`, `public/vendor` (downloaded / generated by `tools/setup.mjs`);
* `node_modules` contains only production dependencies — devDependencies like `puppeteer-core` are for development and testing, and packing them into a release would only add size;
* `data/local-assets.json` (only present if the 3D board textures were extracted on this machine): the textures themselves are in `public/assets/local` (about 68 MB, included along with
  `public/assets`), but the game only knows which textures are available through this JSON — shipping the textures without the manifest gives players 68 MB
  of unusable files. When the manifest is missing, you are told to run `node tools/setup.mjs --local` first.
* `test/` is never included (to save space).

Whole-tree copies skip symlinks and **entries starting with a dot**: the packaging machine's `.DS_Store` neither belongs to the project nor should appear in a bundle other people download.

The Node version and sha256 are **pinned in `NODE_PIN` in `scripts/make-windows-bundle.mjs`** (rather than `latest-v22.x`):
otherwise a bundle built today and one built last month would differ, and problems couldn't be reproduced. To change the version you must explicitly pass `--node-version` (a
concrete version written like `vX.Y.Z`) + `--sha256`.

The download cache for the official zip lives in the repository's **`.cache/`** (not in version control), and **`node.exe` is re-extracted from the verified zip every time**:
the extraction target is a newly created temporary directory that is deleted afterwards. The zip is what's cached, not the extracted result — a truncated `node.exe` left behind by an interrupted extraction has no relationship to the verified
zip, so reusing it would mean shipping a broken file; also, the system temp directory is shared on Linux.
The extractor falls back per platform: `tar` (the bsdtar bundled with Windows 10+ and macOS both understand zip) → `unzip` (GNU tar can't extract zip;
this is the tier used on Linux) → Windows' built-in `Expand-Archive`.

About `--out` and `--force`: if `--out` points at **the repository itself or one of its parent directories** it is refused outright; even when it points elsewhere, `--force` only deletes when
"the directory is empty" or "it contains exactly the previous portable bundle (the bundle root has `README-开箱即用.md` and `app\`)",
and in every other case it refuses and leaves the directory alone — path comparisons can't defend against case differences, symlinks, 8.3 short names and similar tricks, so the rule is written the other way round:
it only acts when it can confirm "this is the previous output".

## 5. FAQ

| Symptom | Fix |
|---|---|
| Double-clicking the `.bat` flashes and closes | Run `启动游戏.bat` from a command prompt to see the error, or run `node\node.exe app\scripts\launch.mjs --no-setup` by hand (the `.bat` pauses on a non-zero exit). **Don't drop `--no-setup`**: without it, it goes online to prepare assets, and `node` isn't necessarily on the PATH |
| Says node can't be found | The portable bundle should contain `node\node.exe`; if not, you have a `--no-node` bundle and need to install Node 22/24 LTS yourself |
| Port already in use | Close whatever is using 3000 (`node tools/doctor.mjs` tells you what), or add `--port 3001` to the start command |
| Browser didn't open automatically | Visit `http://127.0.0.1:<port>` by hand; `--no-open` / `SP_NO_BROWSER=1` disables auto-open |
| Friends can't connect | The firewall hasn't allowed private networks, or you're not on the same subnet; diagnose with `node tools/doctor.mjs` (in the source repo, see the firewall section of [DEPLOY.en.md](DEPLOY.en.md)) |
| A "Download File Info" dialog pops up on entering the game | That is a download manager like IDM / Xunlei sniffing the audio URLs — the game isn't downloading anything. Newer versions use the extension-less `/media/…` route instead (see [PR #28](https://github.com/sganggs/Stronghold-Protocol/pull/28)), so it **should no longer pop up**; if it still does, paste the URL from the dialog into an Issue, or add an exception in the download manager (e.g. `http://127.0.0.1:3000/*`) / quit it while playing |
| First entry into the game is slow | Each player downloads a few dozen MB of assets (read from local disk when hosting on this machine); afterwards they come from the browser cache |
| Building on Linux fails to extract | GNU tar doesn't understand zip: install `unzip` (or, where the docs allow, build on macOS / Windows instead) |

## 6. Security and size notes

* The `node.exe` in the portable bundle comes from the official nodejs.org release, is copied only **after verifying the sha256 pinned in the repository**, and is not modified in any way;
  the `LICENSE` from the same archive is also taken out and shipped as `node\LICENSE-node.txt`.
* `app\` contains only the files tracked by version control + production dependencies + assets + the 3D board manifest; local files excluded by `.gitignore`
  (`.env`, `.claude/`, `scripts/service.env.cmd`, etc.) never go into the bundle.
* The game writes nothing to the registry and installs no services; `启动游戏.bat` is only a few lines (switch to the UTF-8 code page → find `node\node.exe` →
  run `app\scripts\launch.mjs --no-setup`).
* To run it as a Windows service that starts on boot, use the repository's `scripts/install-service-windows.ps1` (meant for bundle / source deployments; see [DEPLOY.en.md](DEPLOY.en.md)).
