## 0.3.4 — Unreleased

### New Operators and Modules (CN 2.7.91)

- Added the Custom Squad Operators Toska, Territoriya and Talulah (the new 6★ of CN 2.7.91): all three skills are selectable, Potential and Development follow the player's settings, and Territoriya comes with the Module "Empty Bottles and Cans"; all three are Ursus, and since the second half has no Ursus Alliance they count as support Operators under the rules. Toska is the first "trigger-type effect" support (§37.91).
- Four new Modules can be chosen in Operator Loadout: Horn's "Horn's Special Limited Badge", SilverAsh the Reignfrost's "Invitation", Muelsyse's "'Muelsyse and Friends'" and Astgenne the Lightchaser's "Greetings from Afar". Horn's Module is exclusive to Integrated Strategies, so in Stronghold Protocol only its attributes take effect; SilverAsh the Reignfrost still carries no Module by default (§37.91).
- Clementia's S3: the interval before a tile that was just shelled can be chosen again changes from 5 seconds to 3.5 seconds, per the new data (§37.91).
- The 5★ Olga and Mirror Smith and the 4★ Bell Ringer from the same update are not 6★ and are not on the Alliance list, so they are not added for now; we wait for the list to be released with "Stronghold Protocol: Protocol" opening on November 8 (§37.91).

### Fixes

- Fixed the [Territoriya] spawned by "Demon's Blade" being invisible on screen: the tiles covered by the [Territoriya] are now darkened and outlined in purple, and move with it; the new Operator Territoriya's "Territoriya" shows the same (§37.92).
- Fixed an Operator wearing two identical pieces of Equipment (for example two Advanced Originium Solvents) getting the effect of only one: the second piece's attributes and HP-drain effect would override the first. Each piece is now calculated separately (two Advanced Originium Solvents give ATK +60%+60% and drain 120 HP per second); a normal piece plus an advanced one always stacked and is unaffected (#902, thanks to @Gaoily).
- Fixed enemies such as the Heavy Defender, when blocked again from behind, still winding up their normal attack in the old walking direction and only turning once the attack resolved: they now face the target as the wind-up starts, a display-only change (#869, thanks to @YinqiMargatroid for pinpointing it).
- Fixed the damage-sharing direction of the Chalice of Regret being reversed: the surrounding ground enemies now take only 5% of the damage and the Chalice takes the rest as True damage (before, the enemies took 95% and the Chalice shared only 5%); based on the Chalice talent description on PRTS, changed in all four versions.
- Fixed Ulpianus's S3 [Move] and [Return] not clearing his own elemental damage: [Move] is in essence a retreat and redeploy, and now, as on a normal deployment, it clears Burning, Neural, Apoptosis and other elemental damage and the elemental burst state; other effects are still kept (#903, thanks to @papagayopepe480).
- Fixed "Download all assets" needing the whole package downloaded again after a refresh: Chrome on Windows has an HTTP cache of at most about 320 MB, which cannot hold the roughly 1 GB of full assets, and downloading in order pushes the earlier files out. When opened over HTTPS or on localhost, every downloaded file is now stored in this site's storage (the same place as imported asset packs), used directly after a refresh without requesting the server again, and "Ready" counts them too; over plain HTTP they can still only go into the HTTP cache, and the window explains why (#725, thanks to @RushFTK for providing a test server).
- Duck Lord's "Mystery Customer" corrected from the reporter's three official-server recordings: the replaced enemies are drawn only from the ground enemies of the lower-lane spawn point; the number replaced each round and the enemies replaced are still the same for all four players, while the replacement type is now drawn once per player: the same type when one player has two replaced, but it may differ between players (before, all four were replaced with the same type) (#839, thanks to @ouuuyuuu).
- Ulpianus's S3 [Move] is "always executed", as in the official game: while blocking, when the anchor lands under his own feet, and when neither the anchor's landing tile nor the tile behind it can be deployed on, he still does one [Move] on the spot, which does not take him off his tile but counts as a new deployment (elemental damage is cleared, and on-deploy effects such as the Raid Grenade restart their timers), without placing "Undeviating Course", and he does not return when the skill ends (#903, thanks to @papagayopepe480).
- Fixed the already-hidden Alliance discs and effect bar in the enemy-wave preview during prep still being able to intercept clicks and pop up Alliance details: after the fade-out they are also made invisible, and are restored at once on returning to prep (#892, thanks to @2321Robin for the detailed report).
- Fixed the Strategy-phase name cards cropping out the Operator's face, adjusted the portrait framing of the horizontal name cards, and covered the desktop and landscape-phone sizes (#886).
- Fixed the action box of the selected Operator stacking the screen margin twice after the notched-screen adaptation, restoring its alignment with the selected tile (#889).
- Fixed the room's remove-player / remove-AI button covering the settings dialog: layers inside a seat card no longer go above the top bar's dialogs (#888).
- Fixed the CI add-only FX metadata test failing when Pillow is not installed: the test now explicitly uses PNG and verifies that Pillow is not imported, keeping the merge override; the actual extraction still defaults to WebP (#881).
- Fixed the settings window being hidden together with the room toolbar when a desktop window with settings open is shrunk to landscape-phone height: on a short screen only the tool buttons collapse, and an already opened window stays (follow-up to #888).
- The plugin manifest test also holds under Node 25: the new JSON.stringify can write back any nesting depth, and the error quote is cut to the first 40 characters; older versions still show `[…]`.
- Fixed the action box of the selected Operator drifting away from the Operator on notched phones / PWAs: after #889 switched to viewport-fixed positioning, the old safe-area fallback margin would pull it apart a second time, so Retreat / Sell could not be tapped (found in the post-merge review).
- Summon outfits (cosmetic plugins) now also follow their owner in the detail panel and thumbnails, and respect the "Show other players' skins" switch; in simplified-rendering battles, the summon updates along with it when the owner changes outfit mid-battle (found in the post-merge review).
- Fixed a player who left a multiplayer match before the Strategy pick began still having a Strategy picked for them at the starting HP: they are already eliminated, yet often took Goliath (in the Ultimate with two players and two bots, one leaving, 8 of 20 matches), so the living teammates could not get it, and later bots would take Touch for them. Now, when nobody has taken Touch yet, they take Touch (Field Medic is team-wide and is kept even after its holder is eliminated); otherwise they pick randomly among the remaining Strategies and never take Goliath; while they have not yet picked, other bots no longer take Touch on account of Goliath. Seed-paired on such Ultimate matches (40 matches): HP-pool completion 59.4% → 74.3% (+14.9 ± 5.8), wins 15 → 17 (§37.65).
- Fixed a player who left before the Strategy pick began having the team bar and the result screen show the starting HP of the picked Strategy (for example 28): it is now still the 0 at the time they left (§37.65).
- A player who leaves during the Strategy pick now has a bot pick for them (maintainer's decision): before, they were given the default Strategy Warfarin on the spot, and the living bots often took Touch again on account of Goliath (in the Ultimate with two players and two bots, one leaving as the Strategy pick began, 35 of 40 matches). Now they keep their original place in the order, and when their turn comes they behave like a player who left before the pick began: take Touch when nobody has yet, otherwise pick randomly among the remaining Strategies, never Goliath; HP is still the 0 at the time they left. Seed-paired on such Ultimate matches (40 matches): HP-pool completion 50.4% → 74.3% (+23.9 ± 6.4), wins 10 → 17 (§37.65).

## 0.3.0 — 2026-10-16

### Rules and plugins

- New plugin system: the server owner installs plugins, and the room host turns them on for the whole room in the "Original / Plugins ×N" panel at the top of the room. The original game is always the default; matches with gameplay-changing plugins are marked "Unofficial" and are not counted in the stats Overview by default (the "Include plugin matches" toggle shows them); with only cosmetic plugins on, a match still counts as original.
- Data plugins can change values, the economy and waves, add Operators, enemies and modes, and borrow official skills and assets. The merged data is validated as a whole for references, dependencies and conflicts; blackboard values and the like are capped at 10 times the original's maximum for the same key (at least up to 64), and spawn counts and loop steps have their own limits. Each room uses its own content set, and the match can only start once everyone has downloaded and verified it.
- The DSL can describe skills, talents and preparation effects in JSON, placed directly in data plugins without enabling script execution; it supports triggers, attributes and statuses, damage, healing, summons, and actions on funds, bond stacks, items and more.

### Interface

- Cosmetic plugins can replace avatars, artwork, Spine models, icons, voices, sound effects and music, or directly borrow assets this installation already has. The room host can turn them on for the whole room, and players can turn them on just for themselves in "Settings → Cosmetic plugins"; visuals and music already on the field switch along, and when a single asset fails to load it falls back to the asset below it.
- Interface plugins show widgets such as damage statistics in a separate sandboxed page; each player turns them on or off in "Settings → Interface plugins", and they only read the match information they are allowed to and cannot act on the player's behalf. The title screen can show the plugins installed on the server; the room's plugin panel supports turning plugins on and off, choosing modes, changing plugin settings, and "Apply again" after files change.

### Hosting a server

- The server owner can use `plugins/config.json` to restrict the allowed plugins and classes, fix the room plugins, or play only the original game; `SP_PLUGINS=off|host|fixed` overrides the room policy. Server-side matches with gameplay plugins use a separate child process by default, and browser simulation uses a Worker; when one stops responding, a watchdog takes over or ends that match.
- Script plugins are off by default. `SP_PLUGIN_SCRIPTS=sandbox` uses a sandbox in a browser Worker and a restricted child process, needs no per-player consent and allows listening on the public internet. `trusted` is native trusted execution: the plugin must be reviewed, the lock file hash pinned, and every player in the room must consent; when listening on a public or wildcard address, `trusted-force` must be used explicitly (and a server forwarded through a public reverse proxy should be treated as a public deployment for this choice). The sandbox doesn't replace judging where a plugin comes from either.
- The start scripts have a new `--scripts sandbox` parameter that turns on the plugin script sandbox without setting an environment variable; on Windows just double-click `scripts\start-windows-sandbox.bat` (the Windows ready-to-run bundle also comes with `启动游戏-插件沙箱.bat`).
- When a script set is built for the first time, the registration probe of each uncached plugin takes up to 5 seconds by default, and the lobby may pause briefly during it; on slow machines adjust it with `SP_SCRIPT_PROBE_MS` (500–60000 ms).
- A Content Security Policy (CSP) is on for the whole site by default. `SP_CSP=off` turns the site-wide policy off; the interface plugins' and the simulation Worker's own policies stay in effect. The Docker image keeps the plugin templates and author guide separate from the server owner's plugin volume, so the studio can still create plugins once the volume is mounted.

### Tools

- New "Plugin studio" `/studio/`: open it on the local machine or LAN with the key from the start window, pick a template, find targets by official name, drag and drop assets with a live preview, and package and download in one click. The templates cover cosmetic, values, new Operator, DSL, preparation effects, new mode, interface and script; "Try a battle" compares the original and the plugin on the same scenario with side-by-side replays, while preparation economy effects still have to be checked in a real room.
- Forge workshop packs can be imported: check the conversion report first, then import the compatible cosmetic, values, new Operator, paired new pieces, enemy and language content; when the skills are all official skills of one official Operator, that Operator's official kit is used. The behaviour scripts in `kits/` that match the plugin SDK are combined into one script plugin, which is not run during import and only runs when the server owner enables `SP_PLUGIN_SCRIPTS` and a room selects it; `--no-scripts` or the checkbox in the studio skips it; content that can't be converted comes with the reason.
- Plugins can be installed from a local zip, from an HTTPS address, or by choosing from a community catalogue; remote zips must have their SHA-256 verified. When updating a plugin of the same name, the old folder can be moved to a backup location; the project doesn't host plugins or run a marketplace.
- The plugin list in the plugin studio lets you tick several plugins and remove them at once with "Delete selected": the folders are moved to `plugins/_removed/`, not deleted for good, and moving them back restores them; plugins a room is using (including in a match) are kept, with the reason explained.
- `node tools/plugin.mjs` provides commands to create, check, test, package, import and install, and its error catalogue gives the cause and the fix; the release bundle comes with the author tools, templates, Schemas, test helpers and docs. The plugin API table lists the stable and experimental interfaces; to get started see the [plugin beginner's guide](docs/PLUGIN-GUIDE.md), and for the format see the [plugin reference](docs/PLUGINS.md).
